# Unfold

SaaS that turns a person's existing resume into a live portfolio site with its own link
(`name.unfold.site`, or a custom domain on Pro). Tagline: "Your resume, unfolded into a
portfolio that gets you hired."

@AGENTS.md

## Stack (latest versions; these break older tutorials)

- **Next.js 16**, App Router, TypeScript. `middleware.ts` is now **`proxy.ts`**. `params` is a Promise.
  `PageProps<"/route">` / `LayoutProps<"/route">` are global types generated by `next typegen`.
  Read `node_modules/next/dist/docs/` before using an API you're unsure of.
- **Clerk 7** (`@clerk/nextjs`). `<SignedIn>`/`<SignedOut>` were removed: use `<Show when="signed-in">`.
  Server: `auth()`, `currentUser()` from `@clerk/nextjs/server`.
- **Supabase** (`@supabase/supabase-js` v2) for Postgres + Storage. Clerk is a third-party auth
  provider, so `auth.jwt()->>'sub'` is the Clerk user id (**text**, e.g. `user_2abc…`, not a uuid).
- **AI for resume parsing** (`lib/parse-resume.ts`), chosen by which key is in `.env.local`:
  - The schema includes links and education. `tidyResume()` normalises every result.
  - `GEMINI_API_KEY`: used first if set. Native `generateContent` REST API with `responseJsonSchema`,
    falling back to plain JSON mode. PDFs are sent inline. Model `GEMINI_MODEL`, default `gemini-flash-latest`.
  - `OPENROUTER_API_KEY`: OpenAI-compatible chat completions with a json_schema
    `response_format`. Model `OPENROUTER_MODEL`, default `openrouter/free` (routes to a free model).
    PDFs are converted to text first with `unpdf`. Replies are validated with zod and retried once.
  - `ANTHROPIC_API_KEY`: Claude via `messages.parse` + `zodOutputFormat`. It reads PDFs natively.
    Model `ANTHROPIC_MODEL`, default `claude-sonnet-5-5`.
  - `AI_PROVIDER=gemini|openrouter|anthropic` forces one when several keys are set.
- **zod v4** (`z.email()`, `z.uuid()` are top-level).

## Demo mode

`NEXT_PUBLIC_DEMO_MODE=true` runs everything without Clerk or Supabase:
- `lib/demo.ts` holds the flag.
- `lib/data/index.ts` picks `demoStore` (a JSON file at `.unfold-demo.json`, files in `.unfold-demo-media/` served by `/api/media/[...path]`) instead of `supabaseStore`.
- `proxy.ts` skips Clerk.
- `ClerkShell` renders no provider.
- The sign-in pages redirect to `/dashboard`.

**All data access goes through `store` from `@/lib/data`.** Never query Supabase from pages or actions directly, so both modes keep working. New data needs a method on the `Store` interface (`lib/data/types.ts`), implemented in both stores.

## Rules that must hold

- **RLS everywhere.** Every table has row-level security keyed on `(select auth.jwt()->>'sub')`.
  New tables need policies in a new numbered migration (`0002_…sql`). Never edit `0001` after it's applied.
- **Visitors never read tables directly.** Public pages use `get_public_portfolio(site)` (security definer).
  It returns only published portfolios, only **approved** projects, and email only if `show_email`.
- **Paid fields are server-only.** `profiles.plan`, `portfolios.custom_domain` and `show_badge` can't be
  updated by the `authenticated` role (column grants). Change them with the service role from trusted
  server code (e.g. a Stripe webhook). Never expose the service key to the browser.
- **The AI never invents facts.** Resume parsing uses only what's in the file. Generated case studies are
  drafts (`approved = false`) until the user approves them.
- **Re-upload keeps edits.** It only fills empty fields and adds projects with new titles.
- Clerk is mounted per section, not in the root layout, so portfolio pages on customer domains load no auth code.
- Landing links use plain `<a>` on purpose (full page load drops landing.css, whose `h1`/`h2` rules would leak).

## Design system (follow it for any new UI)

- Dark only. Background `--ink #050506`, surfaces `#111113`/`#18181b`, hairlines `rgba(255,255,255,.07/.12)`.
  Text `--fg #f2f2f4`, `--muted #93939b`, `--dim #5c5c64`. Silver gradient `--silver` is the only accent,
  for primary buttons. Green `--live #8fe3a8` only means "live/success". `--danger #f2a7a0` for errors.
- Type: Hanken Grotesk (display/body, 800 weight for headings with tight negative tracking),
  Instrument Serif italic for one emphasised word in headlines (`<em>`), JetBrains Mono for labels and data.
- Soft corners (12–28px), restrained shadows, inset 1px borders.
- Motion follows Emil Kowalski's design-engineering rules:
  - custom easings `--ease-out: cubic-bezier(0.23,1,0.32,1)` and `--ease-in-out: cubic-bezier(0.77,0,0.175,1)`
  - UI animations under 300ms
  - transition specific properties, never `all`
  - `:active { transform: scale(.97) }` on pressables
  - hover effects inside `@media (hover:hover) and (pointer:fine)`
  - nothing enters from `scale(0)`
  - no animation on keyboard-triggered actions
  - respect `prefers-reduced-motion`
- Class prefixes: landing uses plain names, dashboard `db-*` (analytics `an-*`, inbox `ib-*`), editor `ed-*`,
  templates `mn-/dk-/ix-/cr-/md-/dv-`, contact form `uf-cf-*`, preview bar `tp-`.
  Keep new styles prefixed. In templates, reset link colour with `:where(.xx) a{color:inherit}` (zero specificity)
  so it never overrides button colours.

## Portfolio templates

- All six are free (`tier: "free"` in lib/templates.ts). Adding one = new component + CSS in app/_templates,
  a registry entry, a dashboard note in TEMPLATE_NOTES, and a migration extending `portfolios_theme_check`.
- Templates only get `PublicPortfolio` data: name, headline, bio, location, email (only if shown), skills, links,
  education, avatar, appearance options, contact flag, résumé download, approved projects (with optional image, link,
  stars, language). Images are optional: covers are generated with CSS, so every template must look finished without them.
- Template roots spread `rootAttrs(p)` (data-mode, data-font, data-accent and --t-* variables). Template CSS must read
  colours from its own variables, with a `[data-mode="light|dark"]` block for the non-native mode, use
  `var(--t-accent, <default>)`, `var(--t-display/--t-body, <default font>)`, and set --cf-* for the shared ContactForm.
- Mark every shown field with `ed("field")` / `ed("project.title", id)` (see lib/fields.ts) so the on-page editor can open it,
  and links with `track("project:<id>" | "link:<url>" | "email" | "resume")` for analytics.
- **Any resume must work.** Any field can be empty: a resume may have only a name, have no projects, have 8, or contain
  very long words or non-Latin text. Hide sections that have no data, use `displayName()`, and keep
  `overflow-wrap:anywhere` on the template root. Never invent content (no "Available for work" unless the data says so).
- Never fake data on a real portfolio. Sample/generated content is only for SAMPLE_ID previews and is labelled.
- Each template has its own look on purpose (Minimal/Interactive/Creative/Modern are light, Dark/Developer are dark).
  They are not themed by the Unfold tokens.
- Copy is plain and specific. Buttons say what happens ("Publish site"); errors say what went wrong and how to fix it.
